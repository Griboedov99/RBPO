# RepairTrack

Учёт техники на ремонте — серверное API сервисного центра. Описание продукта: [PROJECT.md](PROJECT.md).

## Что реализовано сейчас

Минимальная запускаемая основа к EK1:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка работоспособности |
| `POST` | `/orders` | Приём устройства: заказ, номер квитанции, код получения |
| `GET` | `/orders/{id}` | Карточка заказа с журналом статусов |
| `POST` | `/public/status` | Статус для клиента по номеру квитанции и коду |

Код получения генерируется случайно (128 бит), в базе хранится только его SHA-256 (D-02). Публичный статус отвечает одинаково на неверный код и несуществующую квитанцию (SR-08).

**Ещё не реализовано:** вход сотрудников, роли и проверка назначения (D-01, D-04), смена статусов и выдача (D-02, D-03). Эндпоинты `/orders` пока доступны без входа — это состояние основы, а не итоговое поведение.

## Запуск

Требования: Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

База SQLite создаётся автоматически в файле `repairtrack.db`. Другой путь задаётся переменной `REPAIRTRACK_DATABASE_URL`.

## Проверка

```bash
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ: `{"status":"ok"}`.

Интерактивная документация API: <http://127.0.0.1:8000/docs>.
